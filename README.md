#  Цифровой двойник диспетчера экстренных служб

> Десктопное JavaFX-приложение, имитирующее работу диспетчера службы 112 / ЕДДС.  
> Принимает сообщение о происшествии, верифицирует звонящего, оценивает срочность  
> и автоматически определяет приоритет (RED / YELLOW / GREEN), формируя наряд-талон.

---

## О проекте

**Цифровой двойник диспетчера экстренных служб** имитирует работу дежурного диспетчера ЕДДС:
принимает сообщение о происшествии, проверяет данные звонящего через внешний HTTP-сервер,
оценивает степень срочности по балльной шкале и направляет соответствующие экстренные службы.

## 2. Функциональные требования

Система должна обеспечивать выполнение следующих функций:

**ФТ-1 — Приём сообщения о происшествии**
Форма ввода принимает: ФИО звонящего, номер телефона, адрес происшествия,
список типов инцидентов с чекбоксами по трём категориям, информацию
о пострадавших (наличие и количество через Spinner).

**ФТ-2 — Верификация звонящего**
Система отправляет HTTP GET запрос к CallVerificationServer. При verified=false обработка блокируется
с описанием причины отказа.

**ФТ-3 — Классификация по приоритету**
Приоритет определяется по типу инцидентов:
- критический инцидент (5 баллов) или наличие пострадавших → RED
- срочный инцидент (3 балла) → YELLOW
- только неэкстренные инциденты (1 балл) → GREEN
Сумма баллов не влияет на повышение приоритета.

**ФТ-4 — Маршрутизация и формирование наряда-талона**
- RED:    все экстренные службы (101, 102, 103, Росгвардия), ETA 5–10 мин,
          номер наряда EM-RED-XXXXX
- YELLOW: полиция (102) и аварийная служба ЖКХ, ETA 15–30 мин,
          номер наряда EM-YEL-XXXXX
- GREEN:  участковый инспектор, плановый выезд 2–6 часов,
          номер наряда EM-GRN-XXXXX

**ФТ-5 — Сохранение данных и экспорт**
Каждое обращение фиксируется в SQLite. Наряд-талон экспортируется в TXT-файл
и PDF-документ с поддержкой кириллицы (PDFBox).
Журнал обращений доступен в отдельном окне с цветовой кодировкой строк
и фильтрацией по произвольному периоду.

## Работоспособность основных сценариев

Система проверена по методу функционального тестирования
(метод чёрного ящика). Все основные сценарии работают корректно.

---

### Сценарий 1 — Экстренный вызов (RED)
Выбран критический инцидент («Пожар с угрозой жизни») или указаны
пострадавшие → система присваивает приоритет RED, формирует наряд
EM-RED-XXXXX, направляет все экстренные службы (101, 102, 103,
Росгвардия), указывает ETA 5–10 минут.

### Сценарий 2 — Срочный вызов (YELLOW)
Выбран срочный инцидент («ДТП без пострадавших», «Угроза насилия»
и др.) без критических → приоритет YELLOW, наряд EM-YEL-XXXXX,
направляются полиция (102) и аварийная служба ЖКХ, ETA 15–30 минут.

### Сценарий 3 — Неэкстренный вызов (GREEN)
Выбраны только неэкстренные инциденты («Жалоба на соседей»,
«Консультация» и др.), пострадавших нет → приоритет GREEN,
наряд EM-GRN-XXXXX, назначается участковый инспектор,
плановый выезд через 2–6 часов.

### Сценарий 4 — Верификация не пройдена
Введён некорректный номер телефона (менее 11 цифр) или адрес
без номера дома → CallVerificationServer возвращает verified=false,
обработка блокируется на втором фильтре, наряд не формируется.

### Сценарий 5 — Сервер недоступен
CallVerificationServer не запущен → система выводит сообщение
«Запустите CallVerificationServer на порту 8282» и не допускает
отправки формы. После запуска сервера обработка выполняется штатно.

### Сценарий 6 — Экспорт наряда
После успешного формирования наряда доступны две кнопки экспорта:
«Сохранить TXT» — создаёт текстовый файл с полным текстом наряда,
«Сохранить PDF» — создаёт PDF-документ с кириллическим текстом
через Apache PDFBox и системный шрифт Arial.

### Сценарий 7 — Журнал и статистика
Все обращения сохраняются в SQLite и отображаются в журнале
с цветовой кодировкой строк (красный / жёлтый / зелёный).
Фильтрация по произвольному периоду через DatePicker и подсчёт
процентного соотношения RED / YELLOW / GREEN работают корректно.

### Принцип работы:

- «Пожар с угрозой жизни» + «ДТП с пострадавшими» → 🔴 RED — все экстренные службы немедленно
- «ДТП без пострадавших» → 🟡 YELLOW — полиция, аварийная служба до 30 мин
- «Жалоба на соседей» → 🟢 GREEN — плановый выезд участкового

## Шкала срочности

| Суммарный балл           | Приоритет | Действие системы                                              |
| ------------------------ | --------- | ------------------------------------------------------------- |
| ≥ 5 или критич. инцидент | 🔴 RED    | Все экстренные службы немедленно (101, 102, 103), ETA 5–10 мин |
| 3 – 4                    | 🟡 YELLOW | Полиция + аварийная служба, ETA 15–30 мин                    |
| 1 – 2                    | 🟢 GREEN  | Участковый инспектор, плановый выезд 2–6 часов               |

### Типы происшествий по категориям

**🔴 Критические (5 баллов) — угроза жизни:**
- Пожар с угрозой жизни людей
- ДТП с пострадавшими / жертвами
- Вооружённое нападение / стрельба
- Обрушение здания / завал людей
- Утечка газа / взрыв

**🟡 Срочные (3 балла) — требуют реагирования:**
- ДТП без пострадавших (материальный ущерб)
- Пожар без угрозы жизни (бытовой)
- Угроза насилия / семейный конфликт
- Кража / грабёж (по горячим следам)
- Затопление / авария коммунальных сетей

**🟢 Неэкстренные (1 балл) — плановый выезд:**
- Мелкое хулиганство / дебош
- Потеря документов / имущества
- Плановая проверка / профилактика
- Жалоба на соседей (шум, бытовой)
- Консультация / информационный запрос

## Верификация звонящего — CallVerificationServer

Отдельный HTTP-сервер (порт **8282**), имитирующий базу данных зарегистрированных звонящих.

**Правило верификации:**
- Телефон: 11 цифр, начинается с «8» или «7» (после нормализации)
- Адрес: не пустой, содержит хотя бы одну цифру (номер дома, км дороги)

```
GET http://localhost:8282/verify?phone=89001234567&address=ул.Ленина,5
→ {"phone":"89001234567","address":"ул.Ленина,5","verified":true,"message":"Данные подтверждены"}

GET http://localhost:8282/verify?phone=12345&address=ул.Ленина,5
→ {"phone":"12345","address":"ул.Ленина,5","verified":false,"message":"Некорректный номер телефона"}
```

Примеры:
- `89001234567` + `ул. Ленина, 5` → ✅ верифицирован
- `12345` + любой адрес → ❌ не верифицирован (меньше 11 цифр)
- телефон без номера дома в адресе → ❌ не верифицирован

## Структура проекта

```
src/main/java/com/emergencydispatcher/
├── EmergencyApplication.java              # Инициализация БД
├── Launcher.java                          # Обёртка для запуска из JAR
├── config/
│   └── UrgencyScaleConfig.java            # Шкала срочности: 15 типов, 3 категории
├── db/
│   └── DatabaseManager.java               # SQLite Singleton: CRUD + статистика
├── model/
│   ├── IncidentReport.java                # Сообщение: ФИО, телефон, адрес, инциденты
│   ├── UrgencyData.java                   # Тип происшествия: название + балл (1/3/5)
│   ├── Appeal.java                        # Обращение: приоритет RED/YELLOW/GREEN
│   └── DispatchTicket.java                # Наряд-талон: тип, заголовок, детали
├── pipeline/
│   ├── Filter.java                        # Интерфейс фильтра
│   ├── FilterException.java               # Исключение фильтра
│   ├── ValidationFilter.java              # Фильтр 1: валидация ФИО, телефона, адреса
│   ├── CallVerificationFilter.java        # Фильтр 2: HTTP запрос к CallVerificationServer
│   ├── UrgencyClassificationFilter.java   # Фильтр 3: подсчёт баллов → приоритет
│   ├── DispatchRoutingFilter.java         # Фильтр 4: маршрутизация + сохранение в БД
│   └── Pipeline.java                      # Оркестратор цепочки фильтров
├── handler/
│   ├── RedHandler.java                    # Экстренное реагирование: 101+102+103, ETA 5–10
│   ├── YellowHandler.java                 # Срочный вызов: полиция + ЖКХ, ETA 15–30
│   └── GreenHandler.java                  # Неэкстренный: участковый, 2–6 часов
├── controller/
│   ├── MainController.java                # Главный экран: форма приёма
│   ├── TicketController.java              # Экран наряда: отображение + сохранение TXT
│   └── JournalController.java             # Журнал + статистика по периодам
└── server/
    └── CallVerificationServer.java        # HTTP-сервер верификации :8282
```
