# Цифровой двойник диспетчера экстренных служб

Десктопное JavaFX-приложение, моделирующее работу диспетчерской службы экстренного реагирования. Система принимает обращения, выполняет их проверку, определяет уровень опасности и формирует наряд с маршрутизацией служб.

---

# 1. Общая характеристика системы

Система поддерживает два режима работы:

## 1.1 Режим оператора

Полнофункциональный интерфейс диспетчера:

* ввод данных заявителя;
* выбор типов происшествий;
* указание пострадавших;
* ручной контроль обработки обращения;
* запуск полной цепочки фильтров.

## 1.2 Режим пользователя

Упрощённый интерфейс подачи обращения:

* выбор происшествия из готовых карточек (preset-ов);
* ввод адреса;
* указание количества пострадавших;
* при необходимости — ввод номера телефона.

---

# 2. Функциональные требования

## ФТ-1 — Приём обращения

Система принимает:

* ФИО (в режиме оператора);
* номер телефона (опционально);
* адрес (обязательное поле);
* минимум один выбранный инцидент;
* количество пострадавших.

## ФТ-2 — Верификация звонящего

Проверка выполняется через внешний HTTP-сервер `CallVerificationServer (порт 8282)`.

* запрос выполняется после базовой валидации;
* сервер возвращает JSON-ответ;
* при `verified = false` обработка полностью блокируется;
* пользователь получает уведомление об ошибке;
* обращение не передаётся дальше по цепочке.

---

## ФТ-3 — Архитектура обработки (Pipes & Filters)

Система реализует архитектуру **«Каналы и фильтры»**.

Объект обработки:
**IncidentReport**

Цепочка фильтров:

1. ValidationFilter
2. CallVerificationFilter
3. UrgencyClassificationFilter
4. DispatchRoutingFilter

При ошибке любого фильтра выполнение прерывается через `FilterException`.

---

## ФТ-4 — Классификация приоритета

Приоритет определяется **ТОЛЬКО суммой баллов инцидентов**.

### Шкала:

* 1–2 балла → GREEN
* 3–4 балла → YELLOW
* 5 и более баллов → RED

Дополнительных правил (по типам происшествий) в текущей версии нет — используется только числовая модель.

---

## ФТ-5 — Сохранение данных

Все обращения сохраняются в SQLite:

* регистрация инцидента;
* результат обработки;
* сформированный приоритет;
* созданный наряд.


# 3. Верификация звонящего (CallVerificationServer)

Отдельный HTTP-сервер

## Правила проверки:

* телефон: 11 цифр, начинается с 7 или 8;
* адрес: не пустой, содержит хотя бы одну цифру.

## Ответ:

```json
{
  "phone": "89001234567",
  "address": "ул. Ленина, 5",
  "verified": true,
  "message": "Данные подтверждены"
}
```

---

# 4. Архитектура системы

## Pipes & Filters

IncidentReport проходит последовательную обработку:

ValidationFilter
→ CallVerificationFilter
→ UrgencyClassificationFilter
→ DispatchRoutingFilter

---

# 5. Модель данных

## Маршрутизация служб

### GREEN

* участковый инспектор
* плановый выезд (2–6 часов)

### YELLOW

* полиция (102)
* аварийная служба ЖКХ
* ETA: 15–30 минут

### RED

* пожарная служба (101)
* полиция (102)
* скорая помощь (103)
* Росгвардия
* ETA: 5–10 минут

## IncidentReport

* ФИО
* телефон
* адрес
* список инцидентов
* количество пострадавших

## UrgencyData

* название инцидента
* балл (1–5)

## Appeal

* приоритет (RED / YELLOW / GREEN)

## DispatchTicket

* номер наряда
* тип
* описание маршрутизации

# 9. Итоговое поведение системы

1. Пользователь или оператор создаёт обращение
2. Система проверяет корректность данных
3. Выполняется верификация через сервер
4. Данные проходят цепочку фильтров
5. Вычисляется приоритет по баллам
6. Формируется наряд и номер заявки
7. Назначаются службы реагирования
8. Данные сохраняются в SQLite
9. Пользователь может экспортировать результат в TXT/PDF
10. Обращение отображается в журнале

### Типы происшествий по категориям

**🔴 Критические (5 баллов) — угроза жизни:**
- Пожар с угрозой жизни людей
- ДТП с пострадавшими / жертвами
- Вооружённое нападение / стрельба
- Обрушение здания / завал людей
- Утечка газа / взрыв

**🟡 Срочные (3 балла) — требуют реагирования:**
- ДТП без пострадавших (материальный ущерб)
- Пожар без угрозы жизни (бытовой)
- Угроза насилия / семейный конфликт
- Кража / грабёж (по горячим следам)
- Затопление / авария коммунальных сетей

**🟢 Неэкстренные (1 балл) — плановый выезд:**
- Мелкое хулиганство / дебош
- Потеря документов / имущества
- Плановая проверка / профилактика
- Жалоба на соседей (шум, бытовой)
- Консультация / информационный запрос
